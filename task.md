# Frontend Engineer Technical Test: AI-Assisted Build

This test is designed to assess how effectively and efficiently a Frontend Engineer candidate uses AI coding tools to build a real product-like interface. The goal is not to judge a specific framework, stack, or agent choice, but to observe the candidate's workflow, judgment, speed, and ability to turn AI assistance into a working frontend outcome.

> [!NOTE]

> **Test summary**

> Build a simple **Mamikos website clone** using any AI agent, coding assistant, framework, library, or tech stack of your choice. You may clone only the **home page**, or expand into additional pages if you want.

### What we care about

- How you use AI tools during development

- How efficient your workflow is

- How well you guide, verify, and refine AI output

- How quickly you turn ideas into a usable frontend

### What we do not restrict

- AI agent or coding assistant

- Tech stack or framework

- UI library or component system

- Project scope beyond the minimum

## Test Task

Create a frontend clone inspired by the **Mamikos** website.

- **Minimum scope:** the landing or home page

- **Optional scope:** additional pages or features if you want to go further

- **Approach:** AI-assisted or vibe coding workflow from start to finish

> [!TIP]

> Keep the scope realistic. A polished, well-documented home page with strong AI workflow evidence is better than a large unfinished project.

## What to Submit

- [ ] Source code repository

- [ ] Working demo link, if available

- [ ] Full screen recording of the end-to-end development process

- [ ] Short readme explaining your approach, tools used, and key decisions

The **screen recording** is the most important part. We want to see how you actually use AI during development, not just the final result.

## What the Recording Should Show

- How you prompt or instruct the AI agent

- How you break down the task

- How you validate AI-generated code

- How you fix errors, adjust output, or improve results

- How you manage time and keep the build moving efficiently

> [!IMPORTANT]

> You do not need to hide mistakes. We are interested in your real workflow, including how you recover from weak AI output, bugs, or wrong assumptions.

## Evaluation Criteria

| Criteria | What we look for |

| --- | --- |

| **Effectiveness of AI usage** | Uses AI as a practical accelerator, gives clear instructions, iterates intelligently, and gets useful output. |

| **Efficiency of workflow** | Moves with focus, avoids unnecessary detours, and uses tools in a time-conscious way. |

| **Engineering judgment** | Does not blindly accept AI output; reviews, edits, validates, and makes sensible decisions. |

| **Frontend quality** | Produces a clean, usable interface that reasonably reflects the intended clone. |

| **Communication** | Explains choices clearly in the recording or readme, especially around AI usage and tradeoffs. |

## Success Looks Like

- A working frontend result, even if the scope is small

- Clear evidence of intentional AI-assisted development

- Fast but thoughtful execution

- Practical decision-making when AI output is imperfect

> [!NOTE]

> **A strong submission**

> A candidate who uses AI deliberately, keeps momentum, verifies output, and ships a decent frontend page will score better than someone who builds more but shows weak workflow control.

## Notes

- You may use any AI coding tool or agent

- You may use any frontend stack

- You may use any supporting library or UI toolkit

- **Expected Effort & Timeframe:** The task is designed to be completed in 3–5 hours of active coding. Please submit within 2 days after receiving this test (let us know if you need additional time due to work/school schedule).

> **Optional guidance for candidates**

> If helpful, structure your session like this: plan the scope, prompt the AI to scaffold, build iteratively, review output often, fix issues quickly, and finish with a short explanation of what the AI helped with most.

> **How well can you use AI to build frontend products effectively and efficiently?**
